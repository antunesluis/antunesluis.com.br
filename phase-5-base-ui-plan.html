Resumo do diagnóstico

Três migrações têm ganho real; os itens hipotéticos devem sair

O repositório não contém selects, tooltips, popovers nem dropdowns de ações. Há, porém, três superfícies modais próprias com lacunas de acessibilidade: confirmação de exclusão, busca e navegação mobile. O menu administrativo é navegação responsiva, não um menu de ações, e precisa apenas de uma correção nativa e localizada.

Migrações Base UI 3 superfícies
Wrapper justificado 1 confirmação
Consumidores do Dialog antigo 2 exclusões
Primitives sem uso real 4 excluídas

Problemas concretos

  • O diálogo de exclusão não fecha com Escape, não contém o foco e não restaura o foco ao gatilho.
  • A busca só trata Escape quando há resultados e também não contém nem restaura foco.
  • O painel mobile fechado continua montado com links focáveis e não trata Escape.
  • O menu administrativo recolhido mantém links fora da área visível alcançáveis por teclado; logout usa link para uma ação.

Pontos já adequados

  • Tailwind v4 e tokens de tema já concentram a identidade visual.
  • Botões, inputs de texto e checkbox usam elementos nativos e estados disabled.
  • As ações de exclusão já preservam estado pending e retornos controlados.
  • Vitest, Testing Library e a CI atual já permitem cobertura direcionada sem novo framework de E2E.

Decisões técnicas recomendadas

Usar primitives específicas e manter a camada local mínima

Imports e composição

  • Instalar somente @base-ui/react como biblioteca de UI nova.
  • Importar pelos subpaths oficiais @base-ui/react/alert-dialog e @base-ui/react/dialog.
  • Usar a API render do Base UI para compor gatilhos sem criar botões aninhados.
  • Não criar provider, registry, factory ou reexport genérico de primitives.

Wrapper local

  • Criar somente ConfirmationDialog em src/components/ui/.
  • Reutilizá-lo nas exclusões de post e projeto, mantendo os contratos públicos desses botões.
  • Manter busca e painel mobile com Base UI direto no próprio componente.
  • Remover Dialog.tsx e seu export somente após os dois consumidores migrarem.

Foco e fechamento

  • Focar explicitamente Cancelar na confirmação e o input na busca.
  • Restaurar o foco ao gatilho ao fechar cada superfície.
  • Permitir Escape quando o componente estiver interativo.
  • Bloquear cancelamento e fechamento enquanto a exclusão estiver pending.

Estilo e estado

  • Transportar as classes Tailwind atuais para Backdrop, Popup, Trigger e ações.
  • Usar os data attributes do Base UI apenas para abertura, fechamento e transições já existentes.
  • Preservar textos, dimensões, cores, sombras, tokens e dark mode.
  • Usar aria-busy, disabled real e nomes acessíveis sem introduzir redesign de loading.

Stacking de portals

Validar o portal contra Header, Toastify e conteúdo administrativo. Alterar src/app/layout.tsx com um root isolado somente se o smoke test demonstrar conflito real de stacking; não adicionar essa estrutura preventivamente.

Escopo e fora de escopo

Somente migrações com consumidor e risco atual demonstrados

Incluído

  • Dependência @base-ui/react e lockfile.
  • Confirmações de exclusão com AlertDialog.
  • Shell modal da busca com Dialog.
  • Navegação mobile com Dialog posicionado.
  • Correção nativa do disclosure e logout de MenuAdmin.
  • Testes direcionados, smoke visual e validação completa existente.
  • Push, PR para main, CI e triagem do Code Review após aprovação da implementação.

Fora de escopo

  • Menu ou DropdownMenu para as listas administrativas.
  • Select, Tooltip, Popover, Drawer e um componente genérico Sheet.
  • Migração completa da busca para Combobox ou Autocomplete.
  • Mudanças em Button, inputs, checkbox, cards, tipografia, layout ou tokens.
  • Unificação dos componentes de exclusão ou das features blog e projects.
  • Novo framework de E2E, meta de cobertura ou alteração estrutural da CI.
  • Tradução de textos, redesign, animações novas ou refatorações não relacionadas.

Ordem de migração

Um componente por vez, com validação antes do próximo

Preparação

Partir de main atualizado e instalar a única biblioteca de UI

Objetivo

Isolar a fase e manter a linha de base reproduzível.

Alteração proposta

Após aprovação, atualizar main, criar refactor/base-ui e instalar @base-ui/react com npm.

Áreas afetadas

Git, package.json e package-lock.json.

Riscos

Implementar sobre commit diferente do analisado ou alterar dependências além da necessária.

Validação necessária

git status --short, revisão do lockfile, npm test, npm run lint e npm run build.

Migração 1A

Introduzir ConfirmationDialog e migrar a exclusão de posts

Objetivo

Substituir a primeira confirmação sem alterar o contrato de DeletePostButton.

Alteração proposta

Criar wrapper mínimo sobre AlertDialog; compor o gatilho atual; preservar conteúdo, classes, backdrop, Cancelar, Ok e fluxo assíncrono.

Áreas afetadas

src/components/ui/ConfirmationDialog.tsx, export de UI, DeletePostButton.tsx e testes novos.

Riscos

Botão aninhado, fechamento durante pending, ação duplicada, foco inicial ou restauração incorretos.

Validação necessária

Abertura por clique e teclado; foco em Cancelar; ciclo de Tab; Escape; backdrop; retorno ao botão de lixeira; disabled e aria-busy; confirmação executada uma vez; aparência em ambos os temas.

Migração 1B

Migrar a exclusão de projetos e retirar o Dialog antigo

Objetivo

Concluir todos os consumidores antes de remover a implementação anterior.

Alteração proposta

Migrar DeleteProjectButton para o wrapper validado; depois remover Dialog.tsx e seu export.

Áreas afetadas

DeleteProjectButton.tsx, Dialog.tsx, src/components/ui/index.ts e testes.

Riscos

Divergência entre os fluxos de post e projeto ou referência residual ao componente removido.

Validação necessária

Mesmos cenários da exclusão de post, retorno de erro preservado, toast preservado e rg sem import ou uso do Dialog antigo.

Migração 2

Migrar somente o shell modal da busca

Objetivo

Delegar foco, isolamento modal e fechamento ao Dialog sem reescrever a busca.

Alteração proposta

Usar Base UI diretamente em SearchButton; remover listeners manuais de outside click e Escape; manter filtro, setas, Enter, links, reset de estado e layout.

Áreas afetadas

src/components/ui/SearchButton/SearchButton.tsx e seu teste existente.

Riscos

Duplo tratamento de teclado, perda do foco no input, reset antecipado, mudança no clique externo ou conflito entre Dialog e listbox.

Validação necessária

Abrir; focar input; fechar com Escape com zero ou vários resultados; restaurar foco; buscar; navegar com setas; selecionar com Enter e clique; verificar nenhum resultado; preservar visual.

Migração 3

Migrar a navegação mobile para Dialog posicionado

Objetivo

Transformar o painel lateral em modal realmente fechado, contido e operável por teclado.

Alteração proposta

Usar Dialog diretamente com popup à direita; transportar backdrop, largura, borda, sombra e transição; fechar ao selecionar link ou mudar pathname.

Áreas afetadas

src/components/layout/HeaderMobileNavigation.tsx e teste novo.

Riscos

Flash do painel, animação diferente, scroll lock inesperado, stacking, foco em links fechados ou fechamento durante navegação.

Validação necessária

Viewports abaixo e acima de md; abrir e fechar por gatilho, botão, backdrop, link e Escape; foco inicial, ciclo de Tab e restauração; ausência de links focáveis quando fechado; light e dark.

Ajuste relacionado

Manter MenuAdmin como navegação nativa e corrigir seu estado recolhido

Objetivo

Corrigir semântica e teclado sem forçar um Menu de ações inadequado.

Alteração proposta

Separar apresentação mobile e desktop no mesmo componente; expor aria-expanded e aria-controls; não renderizar conteúdo mobile fechado; trocar logout por botão real disabled durante pending.

Áreas afetadas

src/features/admin/components/MenuAdmin.tsx e teste novo, sem wrapper compartilhado.

Riscos

Duplicação acidental de navegação, classes divergentes entre breakpoints, logout acionado duas vezes ou fechamento incorreto após rota.

Validação necessária

Mobile fechado sem links alcançáveis; abrir e fechar; mudança de pathname; desktop sempre visível; links corretos; logout uma vez; botão e conteúdo pending acessíveis.

Fechamento local

Executar regressão funcional, visual e pipeline completo

Objetivo

Concluir a implementação sem regressão de UI, tipos, testes ou build.

Alteração proposta

Revisar o diff, fazer smoke público e administrativo e executar a sequência completa da CI existente.

Áreas afetadas

Componentes migrados, fluxos de exclusão, busca, navegação, suíte, lint e build.

Riscos

Validação necessária

npm test, npm run lint, npx drizzle-kit push com ambiente isolado e npm run build; smoke de mouse, teclado e leitor de árvore acessível.

Objetivo

Alteração proposta

Áreas afetadas

Branch remota, Pull Request, GitHub Actions e comentários de review.

Riscos

Validação necessária

Todos os jobs verdes; diff final restrito; cada comentário classificado por validade, escopo e risco; correções válidas revalidadas localmente antes de novo push.

Riscos de comportamento, acessibilidade e visual

Os maiores riscos estão em composição, foco e portals

Comportamento

  • Fechar diálogo antes da conclusão da Server Action.
  • Disparar exclusão ou logout mais de uma vez.
  • Perder reset, seleção por Enter ou navegação da busca.
  • Não fechar navegação após Link ou mudança de pathname.

Acessibilidade

  • Foco inicial diferente do atual ou sem restauração.
  • Conteúdo fechado ainda alcançável por Tab ou leitor de tela.
  • Escape ignorado ou permitido durante pending.
  • Nome, descrição, estado busy ou disabled não anunciados.

Regressão visual

  • Portal alterar stacking com toast, header ou backdrop.
  • Body scroll lock causar deslocamento lateral.
  • Data attributes alterarem timing de transição.
  • Diferenças de cor, largura, padding, sombra ou dark mode.

Mitigações

  • Captura visual antes e depois em viewports equivalentes.
  • Teste e smoke imediatamente após cada componente.
  • Sem mistura com redesign ou extração entre features.
  • Remoção do legado apenas após todos os consumidores.

Estratégia de testes

Caracterizar contratos próprios, sem retestar internals da biblioteca

Automatizados necessários

  • ConfirmationDialog: abrir, cancelar, Escape, foco inicial, restauração, confirm uma vez e bloqueio pending.
  • Exclusões: um caso por feature garantindo action correta, fechamento e toast de sucesso ou erro preservado.
  • Busca: manter Enter existente; adicionar foco, Escape sem resultado, restauração e seleção por clique.
  • Mobile: abrir, fechar por todos os caminhos, pathname, conteúdo ausente fechado e foco restaurado.
  • MenuAdmin: disclosure, breakpoints por estrutura, mudança de rota e logout disabled/pending.

Não adicionar

  • Snapshots extensos de classes Tailwind.
  • Testes de implementação interna do Base UI.
  • Testes para Select, Menu, Tooltip, Popover ou Drawer ausentes.
  • Novo runner, framework E2E ou meta de cobertura.
  • Duplicação de todos os casos entre post e projeto.

Smoke manual acessível

  • Tab e Shift+Tab contidos em cada modal.
  • Foco visível do gatilho ao popup e de volta.
  • Escape, backdrop, botão de fechar e link.
  • Leitura de título, descrição, busy e disabled na árvore acessível.
  • Mouse e teclado em exclusão, busca, mobile e admin.

Regressão e CI

  • npm test.
  • npm run lint.
  • npx drizzle-kit push no ambiente de validação.
  • npm run build.
  • Workflow atual intacto: install, test, lint, schema e build.

Critérios de conclusão

A fase termina com menos código modal próprio e nenhuma primitive sem uso

  • As duas exclusões usam o mesmo ConfirmationDialog sobre AlertDialog.
  • O Dialog antigo não tem consumidores e foi removido.
  • Busca e navegação mobile usam Dialog diretamente, com aparência preservada.
  • Foco inicial, contenção, restauração, Escape, disabled e pending foram validados.
  • MenuAdmin continua navegação nativa e não expõe controles fechados ao teclado.
  • Nenhum DropdownMenu, Select, Tooltip, Popover, Drawer ou Sheet genérico foi criado.
  • Não houve redesign nem migração de controles simples.
  • Suíte completa, lint, schema, build e CI estão verdes.
  • O PR aponta para main e todos os comentários do Code Review foram triados por validade e escopo.
